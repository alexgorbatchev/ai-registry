# Registry CLI Package

This package implements the repository build, bootstrap, and synchronization commands for harness configuration output generation.

## Commands

- Dev / Build: `just build` from repository root. Recipes in this package's `justfile` that run registry commands set their working directory to the repository root, because the commands resolve the registry from the working directory.
- Test: `just registry-cli test` from the repository root, or `just test` in this package; tests resolve repository paths from their own location, never the working directory, and build tests copy `harnesses/` instead of building from it
- Test isolation: `bunfig.toml` preloads `src/__tests__/setup.ts`, which clears every inherited `AI_REGISTRY_*` variable so tests never read this machine's overlays or workspaces and points `CLAUDE_CONFIG_DIR` at scratch space so builds never touch the real Claude Code `.claude.json`; a test that exercises one sets it explicitly. Both this package and session-analysis preload an owned fixture root, set `TMPDIR` beneath it, and import `factory_testRoot` or `factory_testDirectory` through their local `./fixtures` entrypoint. Roots register suite cleanup; per-test directories register `onTestFinished` cleanup. The shared `src/bin/run-tests.sh` supervisor gives each test command a unique scratch directory and terminates its process groups before removal on failure or interruption. Use the `just` recipes for supervised runs. The `test` and `coverage` recipes pass `--timeout` as a hang guard because tests spawn real Git, gitleaks, and builds; do not add per-test timeouts as performance budgets.
- Coverage: `just coverage` from the repository root or this package.
- Validate: `just check` in this package runs `fmt-check` (Oxfmt), `lint` (Oxlint), `typecheck`, `unused` (ts-unused), and `coverage`; `just fix` applies formatting and lint fixes. It runs `bun test` with lcov output inside the command’s unique `.tmp/test-run.*/coverage/` directory and `src/bin/check-coverage.ts`, which fails below 90% line or 90% function coverage across all non-test `src/**/*.ts`, excluding `__tests__/` and `scripts/`; an optional second argument replaces that source glob for packages without a `src/` tree, as `harnesses/claude-code/hooks` uses. Files no test loads count as fully uncovered: every non-blank line and every function or arrow of their type-stripped code; type-only modules have no runtime code and are skipped. The supervisor removes the coverage report after the gate consumes it; the printed metrics remain in command output.
- Scheduled update: `just scheduled-update` from repository root; the entrypoint owns runtime directory creation, logging, and the native macOS/Linux lock for both manual and scheduled runs. Keep only the last 48 hours of timestamped output in `.state/scheduled-update.log`, pruning under the same lock as all log writes and worker execution. Do not add an outer scheduler lock or invoke its internal logger or worker directly. `AI_REGISTRY_SCHEDULED_WORKER` is internal launcher-to-logger transport, not user configuration.

## Boundaries & Quality Rules

- For executable behavior changes, add or update meaningful behavioral tests and apply the root [testing and coverage policy](../../AGENTS.md#development-workflow): at least 90% line coverage and 90% function coverage across this package's non-test source, including unexecuted files and excluding `scripts/` directories. Document and configure the command, source scope, metrics, and exclusions; handle blocking baseline failures under the prerequisite-repair policy. Do not weaken gates or make token test edits.
- Always verify generated harness outputs in `.output/` after changing build or harness logic.
