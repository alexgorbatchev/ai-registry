# Go build storage and temporary files

- Keep each project's combined temporary files, build outputs, test/coverage/profiling artifacts, and project-owned caches at or below **5 GB (5,000,000,000 allocated bytes)** across its checkout and worktrees. Count external output directories too; moving artifacts does not reset the budget. Measure physical storage once without adding nested totals.
- Resolve `go env GOCACHE GOMODCACHE GOTMPDIR GOBIN GOPATH` and inspect actual build flags and output paths before building. Measure the affected storage before and after builds, tests, coverage, and profiling; monitor during long-running commands. Stop further artifact-producing work when the limit is reached or a run would exceed remaining headroom, then clean verified disposable artifacts and remeasure before resuming.
- Keep task scratch files under a dedicated project `.tmp` child. Create it before assigning its absolute path to `GOTMPDIR` for the command. Register cleanup when creating temporary files; remove them immediately after their last consumer finishes, including on failure or cancellation. Avoid `-work` unless investigating compiler output, and remove its retained work directory immediately after inspection.
- Delete finished scratch experiments, obsolete test binaries, and intermediate coverage/profile files as soon as their results have been consumed or retained outside disposable storage. Perform a final cleanup before handing off the task; do not wait for an inactivity threshold. Preserve source, fixtures, manifests, lockfiles, requested deliverables, and required diagnostic evidence; count retained generated files toward the budget.
- Inspect ownership, tracked contents, symlinks, and concurrent users before deletion. Remove only exact task-owned disposable paths; do not wipe `.tmp`, `bin/`, or a shared cache by name. Preserve active processes and other agents' artifacts. If required retained or active files prevent compliance, stop new builds and report measured paths, sizes, and the blocker instead of silently exceeding the limit.
- Measure shared build caches separately, once per physical store, and keep each within the same 5 GB ceiling. Coordinate their users before authorized cleanup. Go's age-based eviction does not establish a size cap. Use `go clean -cache` only when the entire resolved build cache may be discarded; it is broader than one project's outputs. `go clean -testcache` expires test results and is not a build-cache size remedy. Never use `go clean -modcache` as routine build cleanup: it removes downloaded dependency sources. Preserve offline/private dependencies and installed tools; report oversized dependency stores separately.
- Reuse the normal build cache rather than creating one per command or cleaning before every build. Verify cleanup exit status and final allocated sizes; report any remaining over-budget or protected paths.

Tool contracts: [Go cache behavior](https://pkg.go.dev/cmd/go#hdr-Build_and_test_caching), [environment paths](https://pkg.go.dev/cmd/go#hdr-Environment_variables), and [cleanup scope](https://pkg.go.dev/cmd/go#hdr-Remove_object_files_and_cached_files). Check installed help before choosing flags.
