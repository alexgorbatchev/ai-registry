# Go build storage and temporary files

- Keep artifacts owned by the current task at or below **5 GB (5,000,000,000 allocated bytes)** in total: task-created temporary files, build outputs, test/coverage/profiling artifacts, and caches dedicated to that task. Count these artifacts across checkout, worktrees, and external output paths; moving them does not reset the budget. Keep the same task baseline across retries, resumed sessions, and agent handoffs. Count physical storage once without adding nested totals.
- Exclude artifacts created before this task began, other tasks' outputs, shared/global build caches, downloaded dependencies, installed tools, and runtime data such as sessions, credentials, and databases. A shared cache or output directory exceeding 5 GB does not by itself block task work or authorize cleanup.
- Resolve `go env GOCACHE GOMODCACHE GOTMPDIR GOBIN GOPATH` and inspect build flags and output paths to identify task-owned artifacts. Record a baseline for reused output directories and measure attributable task artifacts before and after artifact-producing runs; monitor long-running commands. Do not charge the entire reused directory to the task. If concurrent writes prevent reliable attribution, report that limitation and continue while actual filesystem space permits; uncertain ownership never authorizes deletion.
- At the task's limit, pause only operations that would increase its counted artifacts. Remove verified task-owned disposable files and remeasure, while continuing independent authorized work. If required task artifacts still cannot fit, preserve them and report their paths, sizes, affected operations, and the required budget or scope decision. Actual filesystem exhaustion is a separate blocker even when caused by excluded storage.
- Keep task scratch files under a dedicated project `.tmp` child. Create it before assigning its absolute path to `GOTMPDIR` for the command. Register cleanup when creating temporary files; remove them immediately after their last consumer finishes, including on failure or cancellation. Avoid `-work` unless investigating compiler output, and remove its retained work directory immediately after inspection.
- Delete task-owned finished scratch experiments, obsolete test binaries, and intermediate coverage/profile files as soon as their results have been consumed or retained outside disposable storage. Perform a final cleanup before handing off the task; do not wait for an inactivity threshold. Preserve source, fixtures, manifests, lockfiles, requested deliverables, and required diagnostic evidence; count retained task-created generated files toward the task budget.
- Inspect ownership, tracked contents, symlinks, and concurrent users before deletion. Remove only exact task-owned disposable paths; do not wipe `.tmp`, `bin/`, or a shared cache by name. Preserve active processes, runtime data, and other agents' artifacts. The task budget grants no authority to delete or reconfigure shared storage.
- Reuse the normal shared build cache; do not create one per command, clear it before builds, or impose the task's 5 GB limit on it. Inspect shared cache sizes or change retention only for separately authorized maintenance or diagnosis of actual disk pressure, coordinating consumers first. Use `go clean -cache` only when that separate authorization covers discarding the entire resolved cache. `go clean -testcache` expires test results and is not a build-cache size remedy. Never use `go clean -modcache` to satisfy a task budget: downloaded dependency sources are excluded. Preserve offline/private dependencies and installed tools.
- Verify any authorized cleanup's exit status and remaining task-owned allocations. Report shared or dependency storage separately only when relevant to the authorized maintenance or an actual disk-space blocker.

Tool contracts: [Go cache behavior](https://pkg.go.dev/cmd/go#hdr-Build_and_test_caching), [environment paths](https://pkg.go.dev/cmd/go#hdr-Environment_variables), and [cleanup scope](https://pkg.go.dev/cmd/go#hdr-Remove_object_files_and_cached_files). Check installed help before choosing flags.
